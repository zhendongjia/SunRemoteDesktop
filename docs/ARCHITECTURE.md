# Architecture

## 目标

项目的核心目标是“镜像当前桌面”，不是让 RDP 协议创建第二个登录会话：

```text
RDP client
    │  RDP/TLS
    ▼
SunRDP ── auth/policy ── local session bridge ── platform capture/input
    │                                         ├─ Windows
    │                                         ├─ Linux X11
    │                                         ├─ Linux Wayland
    │                                         └─ macOS
    ▼
same physical desktop
```

RDP 只负责传输、桌面更新和输入事件。桌面捕获、输入注入、本地账户验证和开机启动属于平台适配层或平台服务层，不能把 Windows 的实现细节泄漏进协议核心。

## 模块边界

- `config`：稳定的 TOML 配置和权限白名单。
- `auth`：协议凭据到平台本地账户验证的适配器。
- `display`：把平台帧转换成 SunRDP 桌面更新，并负责多客户端读取。
- `input`：归一化 RDP 键盘、绝对/相对鼠标事件并交给访问门或当前桌面会话。
- `touch`：接收 MS-RDPEI 原生触摸帧，把一个主触点映射到与鼠标共用且受认证门控制的输入路径。
- `bridge`：定义版本化的服务—会话代理协议，以及各平台的 IPC 实现。
- `host`：组合认证、连接数限制、TLS、显示和输入处理器。
- `session`：协调物理控制台唯一所有者、一个有界接管候选连接，以及断开和显示模式恢复责任的转移。
- `platform`：桌面捕获、输入注入和会话生命周期的跨平台接口。
- `admin`：只编辑配置，不直接承担协议或平台逻辑。
- `service`：操作系统服务入口；Windows 服务和用户会话代理通过本地 IPC 连接。

### 协议实现依赖

SunRDP 是本项目的服务组件和对外名称。当前协议层直接集成第三方 `ironrdp-server` crate，用于标准 RDP PDU 编解码、连接状态机和处理器接口；源码中的 `ironrdp_server` 命名空间仅表示对该第三方依赖的直接调用。认证策略、当前桌面镜像、会话桥、平台后端和服务生命周期均由 SunRemoteDesktop 自身实现。依赖清单和许可信息见 [`../THIRD_PARTY.md`](../THIRD_PARTY.md)。

## Windows 服务与控制台代理模型

当前 Windows 实现使用下列模型：

### 系统服务

- 当前以 `LocalSystem` 运行，以便在无人登录时为物理控制台创建受约束的捕获代理。
- 开机启动并立即监听 TCP 端口；会话代理缺失时只提供受保护访问页和明确的等待控制台状态。
- 读取 `C:\ProgramData\SunRemoteDesktop\config.toml`。
- 用 `LogonUser` 验证本地账户密码，再应用白名单。
- 管理 TLS 私钥、连接数、审计日志和会话代理连接。
- 通过受 ACL 保护的版本化命名管道与会话代理通讯。

### 服务管理的物理控制台代理

- 服务读取 `WTSGetActiveConsoleSessionId`，复制自身的 LocalSystem 令牌、设置目标 Session ID，并用 `CreateProcessAsUserW` 启动隐藏代理；不依赖用户登录启动项。
- 代理只附着到当前物理控制台的 `winsta0\\default`、`winsta0\\winlogon` 或 `winsta0\\screensaver` 输入桌面，并在输入桌面变化时退出，由服务立即按新桌面重建。
- 在该控制台 Session 和桌面中调用桌面捕获 API。
- 接收服务转发的键鼠事件并调用 `SendInput` 或更细粒度的输入 API。
- 将帧通过命名管道/共享内存送回服务。
- 用户登录、注销或控制台 Session 变化后，服务撤销旧代理并跟随新的物理控制台。
- 代理启动时确认自身 Windows Session ID 等于 `WTSGetActiveConsoleSessionId`；服务端还独立检查命名管道客户端进程的令牌必须为 LocalSystem。来自普通 Windows RDP 登录会话或交互式用户令牌的代理不得提供画面或接收输入。

这样服务不会错误地把 Session 0 或普通 RDP 登录 Session 当作物理桌面，也能在无人登录时捕获与本地显示器一致的 Windows 登录/锁屏桌面。系统登录仍由 Windows Credential Provider 完成；SunRemoteDesktop 不实现替代登录流程或放宽安全桌面策略。

### 会话桥协议 v2

- 代理连接后先发送魔数、协议版本、桌面尺寸和能力标志。
- 代理到服务方向传送带尺寸校验的紧密 RGBA 帧；单帧上限为 128 MiB。
- 服务到代理方向传送有类型的键盘、鼠标和显示模式请求。
- 代理端帧源使用 latest-frame 语义。管道写入变慢时最多保留正在发送的帧和最新帧，不会按帧率无限积压内存。
- 正式服务的命名管道拒绝远程客户端，使用 first-instance 防抢占，并通过 DACL 只允许 LocalSystem；服务还校验实际客户端进程令牌。测试模式才会使用允许管理员和交互式用户的扩展 ACL。
- 代理断开后服务保留 SunRDP 核心并等待代理重连。帧自带实时桌面尺寸，Windows 显示模式变化不再要求重启服务。
- Windows 在锁屏、PIN 登录和安全桌面之间切换时会替换控制台代理。服务在交接期间最多保留最后一帧 3 秒，并维持已认证连接和显示策略；新代理首帧会取消宽限计时。只有宽限期内没有代理恢复时才进入等待控制台页面，避免正常 `winlogon`/`default` 切换看起来像 RDP 掉线。

RDP 初始画布采用客户端在握手中请求的尺寸，登录前界面始终按该画布渲染。账户认证成功后，若共享屏幕尺寸与客户端不同，真实桌面仍保持隔离，直到用户明确选择以下策略之一：

- 缩放显示：保留共享屏幕当前模式，用 SIMD 双线性插值等比例缩放到客户端画布；比例不同时居中增加上下或左右留边，并只按实际画面视口反向映射绝对鼠标坐标。
- 匹配显示器：由服务管理的控制台代理请求 Windows 把主显示器改为客户端尺寸。选择后立即以等比例缩放开放真实桌面；若捕获端随后精确匹配客户端尺寸则自动切换为原生 1:1。手机竖屏等尺寸没有对应硬件模式时，Windows 使用宽高比和尺寸最接近的可用模式，剩余差异继续等比例适配，不会阻塞在分辨率错误页。

每个 RDP 传输都有独立的认证门和显示策略状态。一个连接拥有物理控制台时，服务仍保留一个有界候选槽，使后来连接可以完成认证；认证成功后即使两端尺寸相同，也会停在分辨率页并显示独立的“断开其他客户端”复选项。候选连接必须明确勾选后才能继续，随后服务先把显示模式恢复责任转给新所有者，再向其他连接发送断开事件。若旧所有者在接管前自然离线，剩余候选自动继承所有权，不会中途恢复物理显示模式；最终所有者离线后才恢复首个连接前的模式。

SunRDP 同时接收 RDP Display Control 动态虚拟通道中的单主显示器布局请求，并通过 Deactivation/Reactivation 以客户端的新画布尺寸重建图形表面。认证后确认的策略在本次连接中保持不变：缩放策略只更新 RDP 画布，绝不自动修改物理屏；匹配显示器策略对连续窗口事件做防抖，再选择宽高比和尺寸最接近的 Windows 硬件模式。硬件模式无法精确表示任意窗口尺寸时，RDP 画布仍保持客户端请求的精确尺寸，物理帧按比例居中适配。

键鼠控制同时接受 RDP 标准绝对坐标、相对坐标和 FreeRDP Advanced Input 鼠标事件。绝对坐标在等比例缩放模式下按真实桌面视口反向映射；相对鼠标模式在客户端画布内累计位置，按钮事件也携带或继承该位置，并把累计后的绝对坐标同步给登录前访问页的命中测试。SunRDP 会独立发送带像素载荷的 32 位 RDP 箭头指针和实时位置，避免 Windows App 隐藏本地指针后远端无光标，也规避第三方编码器会丢弃零载荷 Default Pointer 更新的问题。

原生触摸使用 Microsoft MS-RDPEI 动态虚拟通道。每个 RDP 连接有独立的 RDPEI 状态，SC_READY/CS_READY 完成后，SunRDP 将首个活动触点的按下、移动和抬起映射为同一条控制台鼠标路径，因此登录前访问页和认证后的物理控制台都支持单指点击与拖动；认证门、只读策略、分辨率映射和客户端隔离仍由共享输入处理器统一执行。额外同时触点暂时忽略，不伪装成多个鼠标点击；真正的多点手势和触摸注入保留为后续平台能力。

当前一次只选择一个服务管理的物理控制台代理和一个共享认证客户端；可以额外存在一个仍受认证门隔离的接管候选连接。多显示器布局和管理界面的控制台状态展示将在后续阶段实现。

## 平台适配路线

### Windows

当前使用 `xcap` 做桌面捕获，使用 Win32 `SendInput` 注入键鼠，使用 `EnumDisplaySettingsW` 枚举硬件模式并由 `ChangeDisplaySettingsExW` 请求主显示器模式，使用 `LogonUser` 做本地凭据验证。捕获、显示模式修改和输入注入只存在于服务管理的控制台代理，系统服务不访问 Session 0 桌面。

### Linux X11

捕获优先考虑 XComposite/SHM 或成熟的 PipeWire 桥接；输入优先使用 XTest。必须识别 DISPLAY、Xauthority 和当前 seat，不能把服务账户环境变量当作用户桌面环境。

### Linux Wayland

Wayland 不允许后台程序无条件读取桌面或注入输入。需要通过 xdg-desktop-portal ScreenCast、PipeWire 和 compositor/desktop-specific input portal 获取用户授权。Wayland 适配应作为独立后端，并在 GUI 中明确显示授权状态。

### macOS

使用 ScreenCaptureKit 或系统屏幕录制接口；输入注入需要 Accessibility 权限。服务/登录项模型要遵循 launchd 和用户登录会话边界。

## 协议与安全

- RDP 监听默认绑定 `0.0.0.0:3390`，以避免和 Windows 自带的远程桌面服务争用 3389。安装规则允许 Domain/Private 网络入站；对于 Windows 识别为 Public 的网络，只允许 `LocalSubnet` 来源，避免把 SunRDP 端口直接暴露给非本地路由来源。检测到 Tailscale 虚拟网卡时，会额外创建不依赖 Windows 网络类别的规则，但同时限定接口为 Tailscale、来源为 `100.64.0.0/10` 或 `fd7a:115c:a1e0::/48`。
- 接受连接后启用 `TCP_NODELAY` 和操作系统 TCP keepalive，空闲 30 秒后每 10 秒探测、连续 3 次失败后回收半开传输。它用于清理由睡眠、掉网或路径切换留下的失联连接；认证后的显式接管仍由会话协调器完成，不依赖 keepalive 猜测控制权。
- 当前 Windows 生产编码能力只广告 NSCodec。实测部分 Windows App 会声明 standalone RemoteFX、持续确认收到 SurfaceBits 数据却保持黑屏；在建立按客户端能力和端到端呈现结果选择编码的机制前，不向生产客户端广告该路径。不支持 NSCodec 的客户端仍可退回标准位图更新。
- 当前原型自动生成自签名 TLS 证书，生产版应支持证书导入、指纹校验或企业证书配置。
- 本地账户白名单为空时拒绝所有连接。
- 服务端不得把来源 IP、NAT/代理出口、Tailscale 节点 ID 或客户端自报名称当作免密码凭据；这些标识可能被多个用户共享或由客户端伪造。免手动输入依赖 RDP 客户端在自身凭据存储中保存账户，并在每次 TLS 连接的 Client Info PDU 中重新提交，服务端仍逐次执行 `LogonUser` 和白名单检查。真正的无密码设备信任必须使用客户端独占且可撤销的私钥或令牌，不能退化为网络位置识别。
- 远程控制可单独关闭，形成只读桌面共享。
- 后续应增加更完整的连接审计、速率限制，以及剪贴板/文件传输的显式开关。
- Windows 登录、锁屏和 UAC 输入桌面的可见性来自受限 LocalSystem 控制台代理；项目不会实现自定义 Credential Provider、伪造独立登录 Session 或降低 Windows 安全策略。需要安全注意序列的系统配置仍受 Windows 平台限制。
